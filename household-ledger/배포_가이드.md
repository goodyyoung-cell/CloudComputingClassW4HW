# 제출 가이드 — GitHub 올리기 + Render 배포

제출물은 **GitHub 주소**와 **Render 주소** 두 개입니다. 아래를 순서대로 따라 하면 됩니다.
터미널 명령은 `household-ledger` 폴더 안에서 실행하세요.

---

## 0. 준비 — 로컬에서 한 번 확인 (선택이지만 권장)

```bash
cd household-ledger
python -m venv .venv
source .venv/bin/activate          # Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt

cp .env.example .env               # Windows: copy .env.example .env
# .env 파일을 열어 DATABASE_URL 을 본인 Supabase 값으로 수정 (아래 1번 참고)

uvicorn app.main:app --reload
```

브라우저에서 http://localhost:8000/docs 가 열리고, 콘솔에 `✅ PostgreSQL(Supabase)에 연결합니다.` 가 보이면 성공입니다.
(`⚠️ SQLite 로컬 폴백` 이 보이면 `.env` 파일명·내용을 다시 확인하세요.)

---

## 1. Supabase 연결 문자열 복사 — ⚠️ 반드시 Pooler 주소

Render 무료 플랜은 IPv4로만 나가는데, Supabase의 Direct 연결(`db.xxx.supabase.co:5432`)은 IPv6 전용이라 **Render에서 연결이 실패**합니다. 반드시 **Pooler** 주소를 쓰세요.

1. Supabase 대시보드 → 상단 **Connect** 버튼
2. **Connection pooling** 섹션 (또는 "Session pooler")
3. URI 복사 — 다음 형태입니다:
   ```
   postgresql://postgres.<프로젝트ref>:[YOUR-PASSWORD]@aws-0-<region>.pooler.supabase.com:5432/postgres
   ```
4. `[YOUR-PASSWORD]` 를 실제 DB 비밀번호로 바꿉니다.

이 값을 로컬 `.env` 와, 나중에 Render 환경변수(`DATABASE_URL`)에 넣습니다.

## 2. GitHub에 올리기

GitHub에서 빈 저장소를 하나 만듭니다 (예: `household-ledger`, README 체크 해제).

그다음 폴더 안에서:

```bash
cd household-ledger
git init
git add .
git commit -m "FastAPI + Supabase(PostgreSQL) 가계부 백엔드 (W4)"
git branch -M main
git remote add origin https://github.com/<본인아이디>/household-ledger.git
git push -u origin main
```

> `.gitignore` 가 `.env` 와 `*.db` 를 제외하므로 비밀번호는 올라가지 않습니다.
> `git status` 로 `.env` 가 목록에 없는지 꼭 확인하세요.

**→ 제출용 GitHub 주소**: `https://github.com/<본인아이디>/household-ledger`

## 3. Render 배포

1. https://dashboard.render.com → **New +** → **Web Service**
2. **Build and deploy from a Git repository** → 방금 올린 저장소 연결/선택
3. 설정값:
   | 항목 | 값 |
   |---|---|
   | Language / Runtime | Python |
   | Build Command | `pip install -r requirements.txt` |
   | Start Command | `uvicorn app.main:app --host 0.0.0.0 --port $PORT` |
   | Instance Type | Free |
4. **Environment Variables** → **Add Environment Variable**:
   - Key: `DATABASE_URL`
   - Value: 1번에서 복사한 **Pooler** 연결 문자열 (비번 채운 것)
5. **Create Web Service** 클릭 → 빌드/배포 로그가 흐릅니다.
6. 완료되면 상단에 `https://<앱이름>.onrender.com` 주소가 생깁니다.

> `render.yaml` 이 저장소에 있어서, 원하면 2단계에서 **Blueprint** 로 선택해도 자동 구성됩니다. 이때도 `DATABASE_URL` 은 직접 입력합니다.

**→ 제출용 Render 주소**: `https://<앱이름>.onrender.com`

---

## 4. 동작 확인 (채점자가 볼 화면)

- `https://<앱이름>.onrender.com/`  → `{"message":"가계부 API 동작 중", ...}`
- `https://<앱이름>.onrender.com/docs`  → Swagger 문서. 여기서 직접 테스트:
  1. `POST /categories` 로 카테고리 1~2개 생성 (예: `{"name":"식비"}`)
  2. `POST /accounts` 로 계좌 생성 (예: `{"name":"현금","balance":100000}`)
  3. `POST /transactions` 로 거래 생성 (예: `{"amount":-9000,"memo":"점심","account_id":1,"category_id":1}`)
  4. `GET /accounts/1` → 거래가 중첩되어 보이고 잔액이 줄었는지 확인
  5. `GET /stats/by-category` → 카테고리별 합계
- **Supabase 대시보드 → Table Editor** 에서 `accounts`, `transactions`, `categories` 테이블에 데이터가 실제로 들어갔는지 확인하면 연동이 증명됩니다.

## 자주 나는 오류

| 증상 | 원인 / 해결 |
|---|---|
| 배포 로그에 `psycopg2` 관련 에러 | 연결 문자열 앞머리 문제. 코드가 자동 변환하지만, 직접 `postgresql+psycopg://` 로 바꿔도 됨 |
| Render에서 DB 연결 타임아웃 | Direct 주소를 썼을 가능성. **Pooler 주소**로 교체 |
| 테이블이 Supabase에 안 생김 | `DATABASE_URL` 환경변수 누락 → SQLite 폴백 중. Render Environment 확인 |
| 첫 접속이 느림 | Render 무료 플랜은 유휴 시 잠들었다가 깨어남(정상) |
| `.env` 가 안 읽힘 | 파일명이 `.env.txt` 가 아닌지 확인 |
